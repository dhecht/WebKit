# JSC Intra-Block Split Opportunity Analyzer

## Overview

This Python script analyzes log files generated by JSC's register allocator to identify intra-block split opportunities and determine which ones were already optimized by the `fixObviousSpills` pass.

The analysis helps prioritize which opportunities would benefit most from implementing intra-block splitting in the register allocator.

## Key Concepts

### Split Opportunity
A temporary variable that was spilled but has multiple "use clusters" within individual basic blocks, suggesting it could benefit from being kept in a register within those blocks.

### fixObviousSpills
An optimization pass that removes redundant spill loads/stores by reusing values already in registers.

### Analysis Insight
- If `fixObviousSpills` already optimized all blocks for an opportunity, implementing splitting would provide no additional benefit (the work is already done).
- Opportunities where blocks remain unfixed are prime candidates for splitting, especially those with high benefit scores and high frequency.

## Usage

```bash
python3 analyze-split-opportunities.py /path/to/split-analysis.log
```

### Example
```bash
python3 analyze-split-opportunities.py /tmp/split-analysis.log
```

## Input File Format

The script expects a log file with the following sections:

1. **Split Opportunity Reports**:
```
=== INTRA-BLOCK SPLIT OPPORTUNITY ===
Spilled: %tmp234 with 4 use clusters (total benefit: 3850.5)
  BB#10 [inst 5-8] 3 uses, density=0.75, freq=1000
  BB#15 [inst 12-18] 6 uses, density=0.86, freq=1000
```

2. **Spill Slot Mappings**:
```
=== SPILL SLOT MAPPING FOR OPPORTUNITIES ===
  %tmp234 -> spill42 (8 bytes)
```

3. **IR Before Register Assignment**:
```
=== AIR BEFORE REGISTER ASSIGNMENT (showing Tmps and StackSlots) ===
Air BB#10:
  Move (spill42), %rax
  ...
```

4. **IR After fixObviousSpills**:
```
=== AIR AFTER fixObviousSpills ===
Air BB#10:
  Move %rbx, %rax  <- optimized from spill42 to register
  ...
```

## Output Files

The script generates two output files:

### 1. Analysis Report (`*_analysis_report.txt`)
A comprehensive human-readable report containing:
- Overall statistics (total opportunities, fix rates)
- Top 10 opportunities by benefit
- Detailed analysis of top opportunities
- List of opportunities that need splitting
- Prioritized recommendations

### 2. CSV Export (`*_analysis.csv`)
A CSV file with all opportunities for further analysis in Excel/spreadsheet tools.

Columns:
- `Tmp`: Temporary variable name
- `Benefit`: Total benefit score
- `Num_Clusters`: Number of use clusters
- `Total_Blocks`: Total basic blocks involved
- `Blocks_Fixed`: Number of blocks optimized by fixObviousSpills
- `Fix_Rate`: Percentage of blocks fixed (0.0 to 1.0)
- `Spill_Slot`: Associated spill slot
- `Basic_Blocks`: List of basic block numbers
- `Priority`: Priority level (CRITICAL, HIGH, MEDIUM, LOW, N/A)

## Understanding the Results

### High-Priority Opportunities
Opportunities marked as CRITICAL or HIGH priority with low fix rates are the best candidates for implementing intra-block splitting:

- **CRITICAL**: Benefit > 1,000,000
- **HIGH**: Benefit > 100,000
- **MEDIUM**: Benefit > 10,000
- **LOW**: Benefit > 1,000

### Fix Rate Interpretation
- **100%**: All blocks were optimized by fixObviousSpills - splitting not needed
- **0%**: No blocks were optimized - strong candidate for splitting
- **Partial**: Some blocks optimized - splitting could help remaining blocks

## Example Analysis

Given the output:
```
%tmp1621    50000000.00    2    0/2    0.0%    CRITICAL
```

This means:
- High benefit (50M)
- 2 use clusters in 2 basic blocks
- 0 out of 2 blocks were fixed by fixObviousSpills
- Priority: CRITICAL
- **Conclusion**: Strong candidate for intra-block splitting
